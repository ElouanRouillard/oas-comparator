# OAS Documentation Comparator

**OAS Documentation Comparator** is a Python tool designed for comparative analysis and quality assessment of **OpenAPI / Swagger** specifications in JSON or YAML format.

It offers a dual approach: a **Command Line Interface (CLI)** for exporting JSON reports, and an **interactive web dashboard (Streamlit)** to explore coverage metrics (descriptions, examples, security, metadata) and inspect granular differences between API versions.

* **`samples/`**: Holds lightweight, valid OpenAPI specifications to test the application immediately after cloning.
* **`output/`**: Directory reserved for exported JSON analysis reports generated via CLI execution.
* **`src/`**: Directory containing all application source code :
  * **`main.py`**: Core CLI logic managing argument parsing, orchestrating comparison tasks, writing outputs, and launching Streamlit.
  * **`analyzer.py`**: Contains the core analysis logic. Validates OAS files, calculates coverage metrics, and categorizes diffs generated by DeepDiff.
  * **`streamlit_app.py`**: Streamlit interface with 3 tabs (File Upload, Overview, Detailed Comparison).
  * **`ui_helpers.py`**: Helper functions used to filter and format data for display in Streamlit.
* **`run.py`**: Main CLI and web server entrypoint for launching the application.
* **`config.yaml`**: Application configuration file.

## Use Cases

### 1. Pure CLI Mode (Structured JSON Export)
Executes a direct analysis in the terminal  to export a domain-specific JSON report containing quality metrics and categorized diffs (`doc_a_only`, `doc_b_only`, `modified`), making it ideal for CI/CD pipelines or automated scripts.
```bash
python run.py path/to/doc_a.yaml path/to/doc_b.yaml -o output/report.json
```

### 2. CLI + Web Dashboard Mode (Local Visual Analysis)
Performs the same analysis as Mode 1 and additionally opens the interactive Streamlit dashboard, caching the results to provide an instant visual interface with coverage metrics and value inspection modals.
```bash
python run.py path/to/doc_a.yaml path/to/doc_b.yaml --ui
```

### 3. Web Server Mode (Standalone / Hosted Service)
Launches the application directly as a standalone web service in browser mode, allowing users to dynamically upload JSON or YAML specifications directly through the browser interface for in-memory analysis without writing report files to disk.
```bash
python run.py --ui
```

## Supported Specifications

* **Formats**: JSON and YAML (`.json`, `.yaml`, `.yml`).
* **Versions**: Swagger 2.0, OpenAPI 3.0.x, OpenAPI 3.1.x.
* **Limitation**: Direct cross-version analysis (e.g., comparing a Swagger 2.0 file against an OpenAPI 3.0 file) is **not supported**. Both specifications must belong to the same major version family.

* Git

1. **Clone the repository**:

## Configuration & CLI Options

### Command Line Arguments

The CLI entrypoint `run.py` accepts positional arguments for the OpenAPI specification files along with several optional flags:

| Argument / Option | Type       | Description                                                                  |
| :---------------- | :--------- | :--------------------------------------------------------------------------- |
| doc_a             | Positional | Path to the first OpenAPI/Swagger file (.json, .yaml, or .yml).              |
| doc_b             | Positional | Path to the second OpenAPI/Swagger file (.json, .yaml, or .yml).             |
| -o, --output      | Option     | Destination path to save the generated JSON analysis report.                 |
| --stdout          | Flag       | Print the JSON output directly to standard output. Cannot be used with --ui. |
| --ui              | Flag       | Launch the interactive Streamlit dashboard.                                  |

### Configuration File
The application uses a `config.yaml` file located at the root directory to define default file paths and runtime settings:

```yaml
# Default directory where CLI json reports are saved
default_output_dir: output

# Temporary file used to share data between CLI and Streamlit
cache_file: .cache/temp_data.json

cli:
  # Output raw JSON to terminal stdout (bool)
  stdout: false

  # Automatically start Streamlit UI (bool)
  ui: false
```

## Explanations

### Quality Metrics
Key indicators calculated to evaluate API documentation completeness:

* **Endpoint Count**: Total number of unique routes defined under the root `paths` object.
* **Description Coverage (%)**: Percentage of HTTP operations (GET, POST, PUT, DELETE, etc.) containing a non-empty `description` or `summary` field.
* **Example Coverage (%)**: Percentage of HTTP operations that provide payload or parameter examples using `example` or `examples` keys.
* **Metadata Coverage (%)**: Percentage of completed root metadata fields out of 8 standard fields (`title`, `version`, `description`, `contact`, `license`, `termsOfService`, `servers`/`host`/`basePath`, and `externalDocs`).
* **Security Coverage (%)**: Percentage of operations protected by local or global security definitions.
* **Top Critical Differences**: Priority-ranked list highlighting key divergences (1. Exclusive routes, 2. Schema divergences, 3. Metadata changes, 4. Text updates).

### JSON Output Structure
When running in CLI mode, the tool outputs a specialized JSON report containing two primary top-level keys:

* **`info_dashboard`**: Contains the computed metrics for both input documents (`doc_a_metrics`, `doc_b_metrics`) and the top priority differences (`top_3`).
* **`data_json`**: Categorizes structural diffs into three primary buckets:
  * `doc_a_only`: Elements present in Document A but removed in Document B.
  * `doc_b_only`: New elements introduced in Document B.
  * `modified`: Existing elements whose value or data type changed between specifications.

Each section (`doc_a_only`, `doc_b_only`, `modified`) contains structured sub-dictionaries:
* `presence`: Boolean flags for top-level metadata fields (`title`, `termsOfService`, `contact`, `license`, `servers`, `externalDocs`, `version`).
* `count`: Aggregated counters categorized by feature (`endpoints`, `schemas`, `parameters`, `responses`, `request_body`, `security`, `tags`).
* `id`: Lists of exact JSON Path expressions (e.g., `root['paths']['/pets']['get']`) pinpointing changed nodes.
* `values`: Extracted values or comparison objects (`old_value` and `new_value`). Stored as single values for `presence` metadata, and as lists for `count` feature categories.


### Cache Mechanism
A temporary cache file (`.cache/temp_data.json`) shares analysis results between the CLI (`src/main.py`) and Streamlit (`src/streamlit_app.py`). It is automatically cleaned up when running in web server mode.
